# Юми — маскот для ML-интерфейса

3D-аватар на VRM, который отражает состояние пайплайна: думает, ищет,
радуется результату, огорчается ошибке. Говорит вслух с липсинком.

Собран так, чтобы подключаться таблицей, а не правками кода.

---

## Быстрый старт

```bash
npm install
npm run dev          # localhost:5173 — страница с окном Юми, ?view=lab — песочница
```

## Подключение к пайплайну

Минимальный вариант — две строки:

```ts
import { connect } from './mascot';

const bridge = connect();
window.fetch = bridge.wrapFetch(fetch, { match: (url) => url.includes('/api/') });
```

Запрос к API переводит Юми в `thinking`, ответ — в `success`, ошибка —
в `error` (через 5 секунд она сама успокаивается). Параллельные запросы
считаются одной волной: `success` приходит, когда вернулся последний.

`match` лучше указывать всегда: без него Юми реагирует на любые запросы
страницы — аналитику, поллинг, загрузку картинок. Свои файлы и `blob:`/
`data:` она пропускает сама; ответы `no-cors` ошибкой не считает. Текст
ошибки вслух не читается — он остаётся в payload для своих правил.

Ограничения: `success` приходит, когда пришли заголовки ответа, — у
потоковых ответов (стрим LLM) это раньше конца текста; висящий запрос
(long-poll) держит волну открытой. Такие запросы лучше исключить в
`match` и сообщать о них событиями вручную.

### WebSocket и SSE

```ts
const off = bridge.listenWebSocket(ws);   // разбирает сообщения сам
bridge.listenEventSource(es);             // то же для Server-Sent Events
off();                                    // отписка только от этого сокета
```

Мост сам достаёт имя события из полей `type`, `event`, `name`, `action`,
`status` или `state` — какой бы из них ни использовал бэкенд.

### Свои правила

```ts
const bridge = connect({
  rules: {
    'rag:search': 'searching',
    'model:done': (p) =>
      p.num('confidence', 1) < 0.6
        ? { state: 'curious', say: 'Я не уверена в ответе.' }
        : 'success',
  },
});
```

Правило — это имя состояния, объект с репликой и жестом, или функция
от данных события. `p.num`, `p.str`, `p.bool` читают вложенные поля
по пути (`'result.score'`) и никогда не бросают исключений.

### Вручную

```ts
import { getMascot } from './mascot';
getMascot().setState('thinking');
getMascot().say('Нашла три подходящих варианта.');
```

## Точки входа

| | что внутри | зависимости |
|---|---|---|
| `mascot` | ядро, мост, голос, `connect`, `getMascot` | нет |
| `mascot/vrm` | `VrmRenderer`, `mount`, `unmount` | three, @pixiv/three-vrm |
| `mascot/react` | `<Mascot/>`, `useMascot()` | react; three грузится лениво |

## Окно Юми

Ретро-окно поверх интерфейса — основной способ встраивания:

```tsx
import { MascotWindow } from 'mascot/react';

<MascotWindow />                                  // слева внизу, всё по умолчанию
<MascotWindow title="помощник" menu={(d) => [...d, { label: 'Ещё', items: [...] }]} />
```

- заголовок перетаскивается; «–» — во вкладку у левого края; «X» — до
  узкой вкладки (голос при этом молчит); «□» — в отдельное окно поверх
  всех окон (Chrome и Edge);
- свёрнутая Юми показывает реплики уведомлением у вкладки;
- меню собирается из данных: массив заменяет стандартное, функция —
  дополняет его;
- положение, режим, кадр и «без звука» запоминаются в этом браузере;
- на узком экране окно уже, на телефоне при первом заходе свёрнуто и
  3D не грузится, пока его не раскроют;
- окно рендерится порталом в `body`; цвета, ширина и `z-index` — CSS-
  переменные `--yumi-*` на `.yumi-window`;
- фон сцены — картинка `bg/room.webp` из папки ассетов; свой фон —
  `backdrop="/путь/к/картинке.webp"`, без фона — `backdrop={false}`.
  Центр картинки стоит за головой Юми; сдвинуть — `--yumi-bg-x`/`--yumi-bg-y`
  на `.yumi-body`, увеличить — `--yumi-bg-size`.

Пиксельный шрифт по умолчанию грузится с Google Fonts. При строгой CSP
или без внешних запросов: `font={false}` и свой шрифт в `--yumi-font`;
для `style-src 'nonce-…'` — проп `nonce`.

На одном ядре — одна картинка: второй `<Mascot/>` или `<MascotWindow/>`
забирает рендерер у первого. Если Юми нужна в двух местах сразу, создайте
второе ядро и передайте его пропом `core`.

## Взгляд

За курсором Юми следит только в покое (`idle`). Во время жестов, танцев
и речи она смотрит в камеру — обращается к пользователю; взгляд
возвращается плавно. Своему состоянию слежение включает `followPointer:
true` (в студии — галочка «следить за курсором»).

## В React

```tsx
import { Mascot, useMascot } from 'mascot/react';

<Mascot renderer={{ fit: 'half', armSpread: 9 }} />

const { state, speaking, set, say } = useMascot();
```

three.js приезжает отдельным чанком, когда `<Mascot/>` впервые
появляется на странице, — первую отрисовку приложения он не задерживает.

## Где лежат файлы

Модель и клипы ищутся от `assetsBase` (по умолчанию `/mascot/`).
Сборки пакета кладут их в `dist-lib/mascot` и `dist-standalone/mascot`
(~13 МБ, на старте грузится ~2.4 МБ: модель и три частых клипа,
остальное — по требованию). Скопируйте эту папку к себе в статику
и укажите, где она:

```ts
<Mascot renderer={{ assetsBase: '/static/mascot/' }} />            // не в корне
mount(el, { assetsBase: chrome.runtime.getURL('mascot/') });      // расширение
mount(el, { assetsBase: 'https://cdn.example.com/yumi/' });       // CDN
```

## Состояния

`idle` · `welcome` · `curious` · `thinking` · `searching` · `analyzing` ·
`comparing` · `excited` · `success` · `gentle` · `error` · `retry` · `speaking` · `dance`

Каждое описано в `core/states.ts`: выражение лица, клип, свечение контура.
Добавить своё — одна строка там же.

`action` может быть списком: тогда каждый раз играет случайный клип из него,
без повтора предыдущего (так устроен `dance`). `resetAfterMs: 'clip'`
возвращает в `idle`, когда клип доиграл, — не нужно подбирать число под
длину анимации. Так устроены `success` и `dance`.

`speakOver: true` — реплика идёт поверх клипа, без перехода в `speaking`:
во время танца или жеста `success` Юми говорит и не прерывает движение. Если клип
кончится раньше реплики, она договорит в обычной речи.

## Камера

Вкладка «Камера» справа в песочнице: кадр (во весь рост, по пояс,
портрет), приближение, сдвиг Юми, поворот вокруг неё, наклон, угол
обзора, поля. На сцене: колесо — приближение, перетаскивание — поворот,
Shift + перетаскивание — сдвиг.

«Сохранить как вид по умолчанию» пишет отличия от встроенного кадра в
`src/mascot/renderers/vrm/camera.json` — так Юми будет стоять во всех
встраиваниях. Для одного конкретного места кадр задаётся опциями, их
песочница даёт готовой строкой:

```tsx
<Mascot renderer={{ fit: 'portrait', zoom: 1.2, yaw: 15 }} />
```

Из кода на лету: `renderer.setCamera({ zoom: 1.5 })`, `renderer.getCamera()`.

**Свой кадр для анимации.** Переключатель «только текущую» на той же вкладке:
ползунки меняют кадр лишь для клипа, который сейчас играет (например, если
в нём Юми уходит вбок). При смене клипа камера плавно переезжает к его
кадру и обратно к общему. Хранится отличиями от общего кадра в
`src/mascot/renderers/vrm/clipCameras.json`; из кода — `renderer.setClipCamera(clip, { zoom: 0.9 })`.

## Студия

Справа в песочнице: выражение лица и его сила, анимация (или случайный
танец), когда вернуться в покой, свечение контура. Юми показывает
результат сразу. «Сохранить» пишет связку под вашим именем в
`src/mascot/core/presets.json` — дальше это обычное состояние:

```ts
getMascot().setState('celebrate');
connect({ rules: { 'model:done': 'celebrate' } });
```

Файл попадает во все сборки. Имя встроенного состояния (`thinking`)
перекрывает его своей версией. Запись в файл работает из `npm run dev`;
в собранной песочнице есть «копировать JSON».

**Лицо по ходу анимации.** Под выбором клипа — таймлайн: пауза,
перемотка, «+ выражение» в текущий момент. Каждая метка — с какой
секунды клипа какое лицо; действует до следующей, переход плавный.
До первой метки и после конца клипа — основное выражение. Пока вы
редактируете, клип крутится по кругу и правка метки его не отматывает;
«показать как будет» проигрывает как после сохранения. В файле это
поле `faceTrack`:

```json
"faceTrack": [
  { "at": 2, "expression": "surprised", "weight": 0.7 },
  { "at": 6, "expression": "happy", "weight": 0.7 }
]
```

**Обрезка.** На том же таймлайне: «⇤ начало здесь» и «конец здесь ⇥»
от текущего момента или числами (применяются по Enter). Обрезанное
затенено, повтор по кругу и «до конца клипа» работают по отрезку. В
файле — `"trim": [2.5, 6]`, секунды исходного клипа; метки `faceTrack`
тоже в секундах исходного клипа, поэтому при сдвиге обрезки не уезжают.

Без файла, прямо из кода:

```ts
import { defineState } from 'mascot';
defineState('celebrate', { expression: 'happy', weight: 0.9, action: 'victory',
  resetAfterMs: 'clip', glow: { color: '#D6457F', intensity: 0.7, pulseHz: 1 } });
```

## Цепочка

Третья вкладка песочницы — несколько состояний или клипов подряд, чтобы
смотреть переходы. У шага: сколько длится (до конца клипа или N секунд)
и за сколько в него вливаться. «Перехлёст» запускает следующий шаг до
конца текущего — переход идёт, пока Юми ещё двигается, а не из
застывшей позы. Цепочка хранится только в этом браузере.

Найденная плавность сохраняется у состояния: в студии ползунок
«плавность перехода», в пресете поле `fadeMs` (по умолчанию 280 мс).
Из кода — разово: `setState('success', { fadeMs: 600 })`.

## Голос

По умолчанию — синтез браузера, бесплатно и офлайн. Липсинк считается
из текста: русские гласные раскладываются по пяти виземам VRM, а события
границ слов подтягивают раскладку к реальной речи.

Заменить на бэкендовый TTS:

```ts
getMascot().setVoiceProvider(myProvider);
```

Если провайдер отдаёт аудио через `onAudio`, автоматически включается
анализ амплитуды и спектра и вытесняет текстовую раскладку. Лицо и тело
об этом не узнают.

## Доступность

Canvas помечен `aria-hidden`: всё, что Юми сообщает, должно дублироваться
интерфейсом. Если в системе включено «уменьшить движение»
(`prefers-reduced-motion`), пропадают покачивание корпуса, микро-саккады
и пульсация свечения; клипы состояний играют как обычно. Переопределить:
`reducedMotion: true | false` в опциях ядра и рендерера.

## Анимации

Только `.vrma` — родной формат VRM, ретаргет не нужен. Клипы с Mixamo
сначала конвертируются в VRMA. Файлы лежат в `public/mascot/anim/`,
подпапки обходятся рекурсивно, так что новый файл песочница подхватит
сама: достаточно обновить страницу. В состояния клип попадает через
реестр в `core/clips.ts`; танцы перечислены в `DANCES`.

Новый файл или обновлённую модель прогоните через сжатие:

```bash
npm run optimize   # assets-src/yumi.vrm → public, все .vrma — на месте
                   # (исходник модели в репозиторий не входит — положите его в assets-src/)
```

Текстуры уходят в WebP, геометрия и анимации сжимаются meshopt без
потерь. Уже сжатые файлы пропускаются. Готовый `gltf-transform` здесь не
годится: он выбрасывает расширения VRM.

Маска решает, какая часть тела слушает клип:

| | |
|---|---|
| `inplace` | всё тело, но с места не сходит — по умолчанию |
| `none` | как есть, вместе с корневым движением |
| `legs` | без ног, таз оставлен |
| `strict` | только верх тела |

У `greeting` маска `none`: клип начинается с корточек и выпрыгивает к
камере. Камера стоит на месте, поэтому в кадре «по пояс» Юми появляется
снизу. Для любого состояния то же включается флагом `rootMotion: true`
(в студии — «двигаться с места, как в клипе»).

## Устройство

```
core/       состояния, очередь, idle-жизнь — без DOM и three.js
renderers/  отрисовка; ядро общается через узкий интерфейс
voice/      синтез, липсинк, акценты речи
bridge/     таблица «событие пайплайна → реакция»
react/      <Mascot/> и useMascot()
```

Ядро не знает про three.js, рендерер не знает про пайплайн, мост не
знает про отрисовку. Поэтому любой слой меняется, не задевая остальные.

## Если что-то пошло не так

Маскот — украшение, он не имеет права ронять приложение. Мост гасит
любые исключения внутри обработки событий, битые данные дают нейтральную
реакцию, не загрузившийся клип просто не проигрывается.
