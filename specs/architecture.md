# Архитектура neiroleptik

## Структура репозитория

```
frontend/              React + TypeScript (Vite), Node 24, npm
backend/               Django — ещё не создан
specs/                 спецификации; этот файл — общая архитектура
.github/               CI и правила совместной работы
```

| Спецификация | О чём |
|---|---|
| `specs/architecture.md` | модули, их связи и принятые решения (этот файл) |
| `specs/mascot.md` | маскот «Юми»: требования, интерфейсы, форматы, приёмка |

## Фронтенд

```
frontend/
  src/main.tsx         точка входа React
  src/App.tsx          выбор страницы: приложение или ?view=lab
  src/sandbox/         WindowDemo — заготовка страницы приложения с окном
                       Юми; Sandbox — лаборатория (см. ниже)
  src/mascot/          модуль Юми (раздел «Модуль маскота»)
  public/mascot/       модель, клипы, фон окна — статика, путь = assetsBase
  scripts/             сжатие ассетов, копирование их в сборки модуля
  vite.config.ts       сборка приложения + dev-эндпоинты лаборатории
  vite.lib.config.ts,  сборка модуля отдельным пакетом и одним файлом
  vite.standalone.config.ts
```

| Команда | Что делает | Где используется |
|---|---|---|
| `npm run dev` | dev-сервер с эндпоинтами записи данных лаборатории | разработка |
| `npm run typecheck` | `tsc -b` по приложению, модулю и конфигам Vite | CI |
| `npm run test:ci` | vitest (happy-dom), один прогон | CI |
| `npm run build` | `tsc -b` + сборка приложения в `dist/` | CI, выкладка |
| `npm run build:lib`, `build:standalone` | модуль для других проектов | по необходимости |
| `npm run optimize` | сжатие модели и клипов (meshopt + WebP) | при замене ассетов |

Экраны продукта появятся вместе с кейсом и заменят заготовку
`WindowDemo`; с Юми они общаются только событиями через мост.

### Связь с бэкендом

Бэкенда пока нет. Когда появится, фронт ходит в него через `fetch`,
обёрнутый мостом Юми (`wrapFetch` с `match` на `/api/`): так запросы
двигают Юми без правок экранов. Поля ответа, влияющие на реакцию
(например, `confidence`), фиксируются в OpenAPI-контракте
(`specs/mascot.md`, 5.4). Отдельного API для Юми бэкенду не нужно.

## Модуль маскота

Спецификация — `specs/mascot.md`.

Юми подключается один раз в корне приложения (`<MascotWindow />`) и
слушает события; экраны о ней не знают ничего, кроме имён событий.

### Слои и направление зависимостей

```
react/ (MascotWindow, Mascot, useMascot)
   │            │
   ▼            ▼ (лениво)
core/ ◄── bridge/          renderers/vrm/ ──► three, @pixiv/three-vrm
   │                          ▲
   ▼                          │ контракт MascotRenderer (core/types.ts)
voice/                        │
                         core знает только контракт
```

| Слой | Ответственность | Главные классы | Не знает про |
|---|---|---|---|
| `core/` | состояния, таймеры, взгляд, реплики, таблица переходов, пресеты | `MascotCore` | three.js, React, источник событий |
| `bridge/` | событие → реакция по таблице; fetch, WebSocket, SSE, DOM | `MascotBridge` | отрисовку |
| `renderers/vrm/` | VRM, клипы и их варианты (маска, обрезка), камера и кадры клипов, свет | `VrmRenderer` | правила, источники событий |
| `voice/` | синтез, липсинк по тексту и по звуку | `Voice`, `BrowserTTS`, `AudioLipSync` | лицо и тело (пишет в «сток») |
| `react/` | компонент, хук, окно с меню, фоном и отдельным окном | `MascotWindow`, `WindowPlacement`, `PipWindow` | правила |
| `assets.ts`, `motion.ts` | загрузка мимо обёртки fetch, настройки движения | — | остальное |

Циклов нет: `core` не импортирует `bridge`, `renderers` и `react`;
`renderers` импортирует из `core` только типы, данные и чистые функции
без состояния (реестр клипов `resolveClip`, дорожка выражений
`faceKeyAt`/`sortKeys`).

### Поток события

```
экран / fetch / WebSocket
        │  bridge.handle('request:done', { confidence })
        ▼
MascotBridge ── правило из таблицы ──► core.setState('success') / say() / playGesture()
                                             │
                     ┌───────────────────────┼────────────────────┐
                     ▼                       ▼                    ▼
           VrmRenderer: лицо, клип,    Voice: речь и        событие core.on:
           свет, взгляд, кадр клипа    липсинк в рендерер   окно показывает пузырь
```

### Жизненный цикл

1. `MascotWindow` монтируется, вставляет свои стили в документ (окно
   может жить в документе отдельного окна, куда стили страницы не
   попадают) и берёт общее ядро `getMascot()`.
2. Код рендерера (three.js, ~207 КБ gzip) грузится лениво, когда окно
   впервые раскрыто; на телефоне — только после раскрытия.
3. Рендерер загружает модель и клипы покоя через `assets.ts` — мимо
   обёртки `fetch`, чтобы Юми не реагировала на свои файлы.
4. Пока рендерер не готов, ядро хранит состояние и таймеры само; готовый
   рендерер получает состояние целиком.
5. При выносе в отдельное окно окно рендерится порталом в его документ;
   рендерер, голос и ядро переключаются на `window` этого документа.
6. Когда Юми не видна, рендерер не рисует кадры (`IntersectionObserver`
   и свёрнутое окно).

### Данные

`presets.json`, `camera.json`, `clipCameras.json`, `transitions.json` —
часть исходников и сборки; пишутся только инструментами лаборатории в
режиме разработки (плагин Vite), проверяются тем же кодом, что и при
загрузке. Форматы — `specs/mascot.md`, 4.8.

### Лаборатория (`?view=lab`)

`src/sandbox/Sandbox.tsx` — страница с инструментами по адресу `?view=lab`:
студия состояний, камера (общий кадр и кадры отдельных анимаций),
цепочки и таблица переходов. В сборке это отдельный чанк, который
грузится только на `?view=lab` (сбой загрузки чанка — сообщение с
кнопкой перезагрузки). Записывать файлы данных она может только у
dev-сервера (эндпоинты есть лишь в `npm run dev`); что доступно в
сборке — `specs/mascot.md`, R23.

### Тесты

Логика ядра, моста, голоса, окна и форматов данных покрыта vitest в
happy-dom (`src/**/*.test.ts`); рендерер подменяется заглушкой по
контракту `MascotRenderer`. Сам three.js-рендерер (камера, клипы, фон)
в happy-dom не запускается и проверяется вручную в браузере — список
таких проверок в `specs/mascot.md`, раздел 8.

### Принятые решения

| Решение | Почему |
|---|---|
| Ядро не знает про three.js, только контракт рендерера | ядро тестируется без WebGL; рендерер можно заменить (2D, видео) |
| Экраны шлют события, реакции — в таблице | смена источника событий (фронт → сервер) не трогает экраны |
| Стили окна вставляются кодом, а не через `.css` | окно живёт и в документе отдельного окна (Document PiP) |
| Файлы данных — JSON в исходниках, а не база | настройки Юми — часть сборки, ревьюятся в PR |
| Ассеты сжаты своим скриптом (meshopt + WebP), а не gltf-transform | сторонние инструменты выбрасывают расширения VRM |
| Фон — картинка на CSS, а не сцена three.js | не нагружает 3D, работает без WebGL |
| Лаборатория в сборке отдельным чанком | не утяжеляет стартовую страницу, доступна на стенде |
