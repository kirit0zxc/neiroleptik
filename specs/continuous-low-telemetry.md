# Постоянная телеметрия Low

Исполнитель с `--telemetry` самостоятельно собирает журналы после успешного
start и подтверждения ACK центром. HTTP API и Event v1 не изменяются.
`agent_id` берётся из авторизованного config, binding — только из сохранённых
успешных, подтверждённых start исполнителя. Заголовок файла не создаёт binding.
Старые подтверждённые экземпляры продолжают дочитываться после stop и рестарта.
Пока ACK не подтверждён, журналы остаются на диске; сбор начнётся после ACK.
История другого исполнителя и экземпляры без подтверждённого start автоматически
не импортируются. Нужно сохранять state и journal-root этого агента.

Один последовательный worker выполняет ограниченный проход одного экземпляра,
конвертацию production mapper и шаг sender. Назначения обходятся по кругу;
ошибка одного журнала не блокирует отправку уже сохранённых событий.
SQLite spool находится рядом со state: `<state.name>.telemetry.sqlite3`. Не запускать ручные
collect/deliver поверх этого spool. Блокировка ExecutionStore защищает владельца.
Heartbeat, команды и lease не ждут диска или HTTP отправителя. При остановке
процесса worker завершается до освобождения блокировки исполнителя.

Raw/checkpoint и очередь долговечны; повторное чтение не создаёт новые Event ID.
Sender повторяет неподтверждённый batch, соблюдает backoff; 401/403 приостанавливают
доставку до перезапуска после исправления доступа, сбор продолжается.
Диагностика содержит состояния/коды и счётчики, без payload, путей и токенов.
Лимиты существующего collector сохраняются: 64 файла, 1000 записей за шаг,
64 MiB сканирования и 256 MiB raw. Превышение требует обслуживания оператором,
автоматического удаления доказательств нет. Поздний новый корень журнала без
доверенной границы процесса по-прежнему блокируется.

Запуск: к обычной команде `python -m agent.runtime.executor ...` добавить
`--telemetry`. С `--once` флаг несовместим. Для live-ленты production API должен
включать поддержку WebSocket (исправление PR №41), publisher и реальные маршруты.

Приёмка: UI start → запросы к настоящему Low → события без ручного collect/deliver;
UI stop → дочитывание; повтор запуска исполнителя не дублирует события.
Автотесты проверяют доверенный экспорт, отсутствие binding до ACK, историю после
stop/restart, сбор и доставку через настоящую SQLite, backoff/ошибки и завершение.

с `--telemetry`, существующая PostgreSQL и Docker Desktop Linux. UI start

появились в уже открытой live-ленте без reload и ручных collect/deliver.

число событий в PostgreSQL осталось 154, повторных записей не появилось.
