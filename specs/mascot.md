# Спецификация: маскот «Юми»

| | |
|---|---|
| Статус | **черновик** — модуль готов; таблица реакций продукта (5.3) появится с кейсом |
| Код | `frontend/src/mascot/`, ассеты — `frontend/public/mascot/` |
| Инструменты | `frontend/src/sandbox/` (лаборатория, `?view=lab`) |
| Ответственный за интеграцию | владелец фронтенда |
| Архитектура | `specs/architecture.md`, раздел «Модуль маскота» |

## 1. Назначение и границы

Юми — 3D-персонаж (VRM) в ретро-окне поверх интерфейса. Она показывает,
что происходит в приложении: думает, пока идёт запрос, радуется
результату, огорчается ошибке, говорит короткие реплики голосом.

**Входит в модуль:** состояния и их смена, мост «событие → реакция»,
3D-отрисовка и камера, голос и липсинк, окно поверх интерфейса с фоном,
инструменты разработки (лаборатория: студия, камера, цепочки).

**Не входит:** бизнес-логика приложения, решение о том, *какие* события
важны (это таблица реакций продукта), серверный TTS (интерфейс есть,
реализации нет), хранение данных пользователя на сервере.

**Главный принцип:** Юми — украшение. Никакой её сбой (нет WebGL, не
загрузился клип, нет голоса) не должен ломать приложение или менять его
поведение (раздел 6).

## 2. Термины

| Термин | Что это |
|---|---|
| Состояние | Именованная реакция: выражение лица, клип, свет, правила возврата. `idle`, `thinking`, `success`… (3.5) |
| Клип | Анимация `.vrma`: имя из реестра `CLIPS` (`core/clips.ts`) или путь к файлу относительно `assetsBase` |
| Разовое / зацикленное состояние | Клип играет один раз (`loop: false`) или по кругу (`loop: true`) |
| Временное состояние | Состояние с `resetAfterMs` — само возвращается в `idle` |
| Пресет | Своё состояние из студии, хранится в `presets.json` |
| Событие | То, что сообщает приложение: `request:start`, `analysis:done`… |
| Правило | Строка таблицы реакций: событие → состояние / реплика / жест |
| Переход | Смена состояния; его плавность (`fadeMs`) — у состояния или в таблице переходов |
| Цепочка | Сохранённая последовательность состояний и клипов для просмотра переходов |
| Кадр | Настройки камеры (`CameraSettings`, 4.8): крупность, сдвиг, поворот, угол обзора |
| Кадр клипа | Отличия кадра для отдельного клипа от общего кадра (`clipCameras.json`) |
| Окно | Ретро-рамка с Юми поверх интерфейса (`MascotWindow`) |
| Фон | Картинка за Юми внутри окна |

## 3. Требования

### 3.1. Поведение

- **R1.** Юми всегда находится ровно в одном состоянии. Неизвестное имя
  состояния (в том числе имена из прототипа объекта: `constructor`,
  `toString`) игнорируется, текущее не меняется.
- **R2.** Временные состояния сами возвращаются в `idle`: через заданное
  время или по концу клипа (`resetAfterMs: 'clip'`). Это работает и когда
  картинки нет (окно свёрнуто, нет WebGL): «по концу клипа» без картинки —
  через 3 с, клип не загрузился — запасной таймер 60 с.
- **R3.** `error` длится 5 секунд, затем `idle`.
- **R4.** За курсором Юми следит только в состояниях с `followPointer`
  (по умолчанию — `idle`). В остальных смотрит в камеру; смена плавная.
- **R5.** Реплика: на время речи — состояние `speaking` с клипом
  `talking`, лицо и свет — от прежнего состояния. После речи — возврат в
  прежнее зацикленное состояние или в `idle`, если до речи был разовый
  жест. Состояния с `speakOver` (`dance`, `success`) реплика не прерывает:
  клип доигрывает, реплика идёт поверх.
- **R6.** Плавность перехода: разовая из вызова `setState(…, { fadeMs })`
  → таблица переходов для пары «из → в» → `fadeMs` состояния → 280 мс.
- **R7.** Юми не реагирует на загрузку собственных файлов (модель,
  клипы, текстуры `blob:`/`data:`), даже если приложение подменило
  `window.fetch` обёрткой моста.
- **R7a.** Состояние со списком клипов (`dance`) каждый раз берёт
  случайный клип, не повторяя предыдущий подряд.

### 3.2. Окно

- **R8.** Окно стоит слева поверх интерфейса, перетаскивается за
  заголовок и не выходит за край экрана.
- **R9.** Кнопки: «–» — свернуть во вкладку у левого края; «□» — вынести
  в отдельное окно поверх всех окон (Document Picture-in-Picture,
  Chromium); «X» — закрыть до узкой вкладки. Из вкладки окно
  возвращается одним кликом.
- **R10.** Закрытое окно молчит; свёрнутое показывает реплики
  уведомлением у вкладки.
- **R11.** Положение, режим, кадр и «без звука» запоминаются в этом
  браузере (`localStorage`, ключ `yumi.window.v1`). Узкий экран не
  перезатирает сохранённое положение: окно лишь рисуется прижатым к краю.
- **R12.** Адаптивность: на узком экране окно уже; на телефоне (< 600 px)
  при первом заходе свёрнуто, и 3D не грузится, пока его не раскроют.
- **R13.** Меню собирается из данных; стандартное — «Вид» (во весь рост,
  по пояс, портрет; в отдельное окно), «Звук» (говорить вслух), «Юми»
  (поздороваться, станцевать, свернуть). Приложение может заменить или
  дополнить его.
- **R14.** Клик по Юми (или Enter/пробел при фокусе) — реакция, по
  умолчанию `welcome`.
- **R14a.** За Юми — фон-картинка (по умолчанию `bg/room.webp`, комната
  с экранами). Центр картинки стоит в точке `--yumi-bg-x`/`--yumi-bg-y`
  (по умолчанию 50 % / 36 % — за головой Юми в кадре по умолчанию
  «портрет»; в кадрах «во весь рост» и «по пояс» точка не сдвигается за
  головой). Края сцены закрыты фоном при любых пропорциях окна, включая
  отдельное окно, и при любых значениях переменных фона. Пока картинка
  грузится или если она не загрузилась — тёмная сцена. Приложение может
  заменить картинку или убрать фон (4.5); без фона сцена — цвета
  `--yumi-body`.

### 3.3. Голос

- **R15.** Голос — синтез браузера; предпочтительный — Microsoft Irina.
  Без неё — лучший доступный русский голос.
- **R16.** «Без звука» — выбор пользователя: реплика остаётся текстом
  в пузыре.
- **R17.** Источник голоса заменяем (`setVoiceProvider`) — для записанных
  реплик или серверного TTS; если источник отдаёт аудио, липсинк
  считается по звуку.

### 3.4. Камера

- **R18.** Камера сама вписывает Юми в кадр по габаритам модели и
  пропорциям окна; поверх — общий кадр из `camera.json` (4.8).
- **R19.** У отдельного клипа может быть свой кадр — только отличия от
  общего (`clipCameras.json`). Когда начинается такой клип, камера
  плавно переезжает к его кадру (около секунды); когда начинается клип
  без своего кадра — так же плавно возвращается к общему. Не заданные в
  кадре клипа поля берутся из общего кадра, поэтому правка общего кадра
  отражается и в клипах. Когда клип остановлен, камера возвращается к
  общему кадру. При `prefers-reduced-motion` кадр меняется сразу, без
  переезда.
- **R20.** Смена настроек кадра или размера окна применяется сразу, без
  переезда (начатый переезд при этом завершается мгновенно).

### 3.5. Встроенные состояния

Источник — `core/states.ts`. Пресеты с тем же именем перекрывают их;
`removeState` возвращает встроенное. Свет (`glow`) у каждого состояния
свой; пульсирует он у `thinking`, `searching`, `analyzing`,
`comparing`, `excited`, `retry` и `dance`.

| Состояние | Лицо | Клип | Повтор | Возврат в `idle` | Особое |
|---|---|---|---|---|---|
| `idle` | neutral | `idle` | да | — | следит за курсором |
| `welcome` | happy | `wave` | нет | 3.2 с | |
| `curious` | surprised | `reacting` | нет | 1.5 с | |
| `thinking` | relaxed | `thinking` | да | — | |
| `searching` | neutral | `lookAround` | да | — | |
| `analyzing` | relaxed | `thinking` | да | — | |
| `comparing` | relaxed | `lookAround` | да | — | |
| `excited` | happy | `victory` | нет | 3 с | |
| `success` | happy | `peace` | нет | по концу клипа | `speakOver` |
| `gentle` | relaxed | `thankful` | нет | 3 с | |
| `error` | sad | `sad` | да | 5 с | холодный свет |
| `retry` | sad | `dismiss` | нет | 2.8 с | |
| `dance` | happy | случайный из `DANCES` | нет | по концу клипа | `speakOver` |
| `speaking` | от прежнего | `talking` | да | — | ставится ядром на время речи |

### 3.6. Лаборатория (инструменты разработки)

- **R21.** Лаборатория открывается по `?view=lab` и грузится отдельным
  чанком: стартовая страница её код не скачивает.
- **R22.** Студия собирает состояние из лица, клипа, обрезки, дорожки
  выражений и света и сохраняет его пресетом; камера настраивает общий
  кадр и кадр текущего клипа; цепочка проигрывает состояния подряд и
  сохраняет плавность переходов.
- **R23.** Записывать файлы данных лаборатория может только у
  dev-сервера (`npm run dev`, 4.9). В собранном приложении эндпоинтов
  нет: студия и цепочка дают «копировать JSON», камера — строку кода
  общего кадра (`renderer={{…}}`); кадры клипов в сборке не
  сохраняются — только в `npm run dev`.
- **R24.** Мышь и колесо на сцене меняют камеру, только пока открыта
  вкладка «Камера». Если в режиме «все анимации» играет клип со своим
  кадром, панель предупреждает, какие поля на экране перекрыты им.

## 4. Интерфейс модуля

### 4.1. Точки входа

| Импорт | Что даёт | Зависимости |
|---|---|---|
| `mascot` | ядро, мост, голос, состояния, `connect`, `getMascot` | нет |
| `mascot/vrm` | `VrmRenderer`, `mount`, `unmount`, настройки камеры | three, @pixiv/three-vrm |
| `mascot/react` | `MascotWindow`, `Mascot`, `useMascot` | react, react-dom; three грузится лениво |

Внутри `frontend/` это файлы `src/mascot/index.ts`, `src/mascot/vrm.ts` и
`src/mascot/react.ts`; имена `mascot…` — для сборки модуля отдельным
пакетом (`npm run build:lib`) в другие проекты.

### 4.2. Встраивание во фронт

```tsx
import { MascotWindow } from './mascot/react';
import { connect } from './mascot';

const bridge = connect({ rules: PRODUCT_RULES });          // таблица реакций, раздел 5.3
window.fetch = bridge.wrapFetch(fetch, { match: (u) => u.includes('/api/') });

<MascotWindow />                                             // в корне приложения, один раз
```

Ассеты лежат в статике фронта (`public/mascot/`, ~14 МБ; на старте
грузится ~2.4 МБ); путь задаётся `renderer.assetsBase` (по умолчанию
`/mascot/`, со слэшем на конце).

### 4.3. Ядро (`MascotCore`, общий экземпляр — `getMascot()`)

| Метод | Вход | Результат |
|---|---|---|
| `setState(name, { fadeMs? })` | имя состояния | смена состояния, событие `state`; неизвестное имя — без изменений |
| `say(text)` | строка | событие `say`, речь (если не выключен звук) |
| `playGesture(clip)` | имя клипа | разовый жест в рамках текущего состояния |
| `setMuted(bool)` / `isMuted` | — | выбор пользователя «без звука», событие `muted` |
| `setVoiceSuppressed(bool)` | — | заглушить голос по решению приложения (не запоминается) |
| `setVoiceProvider(provider)` | `TTSProvider` | заменить источник голоса |
| `on(listener)` | функция | отписка; события — 4.6 |
| `getState()`, `isSpeaking` | — | текущее состояние, идёт ли речь |

Свои состояния без файла: `defineState(name, spec)`, `removeState(name)`.
Своя плавность пары: `defineTransition(from, to, ms)`.

### 4.4. Мост (`MascotBridge`, создаётся через `connect`)

| Метод | Назначение |
|---|---|
| `handle(name, payload?)` | событие по имени |
| `handleRaw(message)` | сообщение, из которого мост сам достаёт имя (`type`/`event`/`name`/`action`/`status`/`state`) |
| `wrapFetch(fetch, { match })` | запросы двигают Юми: `request:start`, `request:done`, `request:error`, `request:cancel`; параллельные запросы — одна волна |
| `listen(target, events)` | DOM-события / свой EventTarget; `detail` — payload |
| `listenWebSocket(ws)`, `listenEventSource(es)` | сообщения сокета и SSE |
| `extend(rules)`, `dispose()` | дополнить таблицу, снять все подписки |

Правило — имя состояния, объект `{ state?, say?, clip? }` или функция от
payload (`p.num('confidence')`, `p.str(...)`, `p.bool(...)`, `p.has(...)` —
читают вложенные поля и не бросают исключений). Функция может вернуть
`null` — событие пропускается.

### 4.5. Окно (`MascotWindow`)

| Проп | По умолчанию | Назначение |
|---|---|---|
| `core` | `getMascot()` | ядро, к которому подключено окно |
| `title` | `yumi` | подпись в заголовке |
| `menu` | стандартное | массив — заменить, функция `(defaults) => …` — дополнить |
| `renderer` | — | опции рендерера: `assetsBase`, кадр (`fit`, `zoom`, `yaw`…) |
| `onMascotClick` | `welcome` | реакция на клик по Юми |
| `storageKey` | `yumi.window.v1` | ключ запоминания |
| `font` | `true` | пиксельный шрифт с Google Fonts |
| `nonce` | — | для CSP `style-src 'nonce-…'` |
| `backdrop` | `true` | фон: `true` — `bg/room.webp` от `assetsBase`, строка — адрес своей картинки (относительный — от `assetsBase`, как модель), `false` — без фона |

Оформление — CSS-переменные `--yumi-*` на `.yumi-window`. Фон — на
`.yumi-body`:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `--yumi-bg-x`, `--yumi-bg-y` | `50%`, `36%` | где на сцене центр картинки |
| `--yumi-bg-size` | `100%` | ширина картинки относительно сцены; меньше нужного для покрытия сцены она не станет |
| `--yumi-bg-ratio` | `4 / 3` | пропорции картинки; для своей картинки задать её пропорции |

### 4.6. Исходящие события ядра (`core.on`)

`state` · `say` · `speaking` · `muted` · `clip` · `ready` · `detached` · `error`.

### 4.7. Рендерер (`VrmRenderer`): камера

| Метод | Назначение |
|---|---|
| `getCamera()` / `setCamera(patch)` | общий кадр |
| `getEffectiveCamera()` | кадр на экране: общий + кадр текущего клипа |
| `getClipCamera(clip)` / `getClipCameras()` | кадр клипа (только отличия) / все кадры клипов |
| `setClipCamera(clip, patch \| null)` | задать или убрать кадр клипа; если клип играет — применяется сразу |

Ключ кадра клипа — тот же, каким клип назван в состоянии: имя из
реестра (`peace`) или путь к файлу от `assetsBase` в кодировке
реестра, каждый сегмент через `encodeURIComponent`
(`anim/vrma/Dwarf%20Idle.vrma`), без суффиксов варианта (`#inplace`,
`@6.4-8.5`). Файл, запущенный из списка лаборатории, играет под
служебным ключом `file:<url>:<маска>`; для кадра он приводится к пути
в той же кодировке без маски (`clipCameraKey`), а файл из реестра — к
его логическому имени. Поэтому кадр, сохранённый из списка, подхватят и
состояния.

### 4.8. Файлы данных (входят в сборку)

| Файл | Формат | Кто пишет |
|---|---|---|
| `core/presets.json` | `{ имя: StateSpec }` | студия лаборатории |
| `renderers/vrm/camera.json` | `Partial<CameraSettings>` — отличия от встроенного кадра | вкладка «Камера», «все анимации» |
| `renderers/vrm/clipCameras.json` | `{ клип: Partial<CameraSettings> }` — поля, заменяющие общий кадр | вкладка «Камера», «только текущую» |
| `core/transitions.json` | `{ transitions: { "из→в": мс }, chains: { имя: ChainStep[] } }` | вкладка «Цепочка» |

Все четыре проверяются при загрузке тем же кодом, что и при записи:
битые записи отбрасываются, числа зажимаются в пределы, остальное
работает.

**`StateSpec`** (`core/types.ts`):

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `expression` | `neutral` · `happy` · `sad` · `angry` · `relaxed` · `surprised` | да | выражение лица |
| `weight` | 0…1 | да | сила выражения |
| `action` | строка или массив строк | нет | клип; массив — случайный без повтора |
| `loop` | boolean | нет | по кругу или один раз |
| `resetAfterMs` | число мс · `'clip'` · `null` | нет | когда вернуться в `idle` |
| `speakOver` | boolean | нет | реплика не прерывает клип |
| `rootMotion` | boolean | нет | двигаться с места, как в клипе |
| `followPointer` | boolean | нет | следить за курсором |
| `fadeMs` | мс | нет | плавность входа в состояние |
| `trim` | `[начало, конец]`, с | нет | играть отрезок клипа |
| `faceTrack` | `{ at, expression, weight }[]` | нет | смена лица по ходу клипа |
| `glow` | `{ color, intensity, pulseHz }` | да | свет-подсветка |

Имя пресета: буквы любого алфавита, цифры, `_`, `-`; до 40 символов.

**`CameraSettings`** (`renderers/vrm/camera.ts`):

| Поле | Встроенное | Пределы | Смысл |
|---|---|---|---|
| `fit` | `full` | `full` · `half` · `portrait` | весь рост, от бёдер, от груди |
| `margin` | 0.08 | 0…0.5 | поля по краям кадра |
| `zoom` | 1 | 0.3…4 | крупность, больше — ближе |
| `offsetX`, `offsetY` | 0 | −1…1 м | сдвиг Юми в кадре |
| `yaw` | 0 | −180…180° | поворот камеры вокруг Юми |
| `pitch` | 0 | −60…60° | наклон камеры |
| `fov` | 28 | 10…60° | угол обзора по вертикали |

**Кадр клипа — замена полей, а не приращение.** При сохранении в файл
попадают поля, которые отличались от общего кадра в тот момент, и дальше
они применяются как есть: если потом изменить в общем кадре то же поле
(например `pitch`), у клипа оно не сдвинется вслед. Поля, которых в кадре
клипа нет, всегда берутся из текущего общего кадра — в том числе из
опций `renderer` приложения и кадра, выбранного в меню окна.

**`ChainStep`**: `{ kind: 'state' | 'clip', name, mode: 'end' | 'secs',
secs: 0.5…60, fadeMs: мс | null }`.

### 4.9. Эндпоинты dev-сервера (только `npm run dev`)

| Маршрут | Метод | Тело | Ответ |
|---|---|---|---|
| `/mascot/presets` | POST | `{ имя: StateSpec }` | `{ saved }` — то, что записано после проверки |
| `/mascot/camera` | POST | `Partial<CameraSettings>` | `{ saved }` |
| `/mascot/clip-cameras` | POST | `{ клип: Partial<CameraSettings> }` | `{ saved }` |
| `/mascot/transitions` | POST | `TransitionsFile` | `{ saved }` |
| `/mascot/anim/manifest.json` | GET | — | `{ files, misplaced }` — список клипов |
| `/mascot/anim/sync` | POST | — | `{ moved }` — разложить клипы, положенные не в ту папку |

Запись перезаписывает файл целиком. Ошибки — `{ error }` со статусом:
405 — не POST; 403 — `Origin` не совпадает с хостом dev-сервера
(подмену `Host` — DNS rebinding — Vite отклоняет сам, но только без
`server.https`); 415 — `Content-Type` не
`application/json`; 413 — тело больше 1 МБ; 400 — не JSON или не
объект (`null`, массив, строка не затирают файл); 500 — файл не
записался. Пути к файлам считаются от папки `frontend/`, а не от
текущего каталога.

Сохранённые файлы не перезагружают открытые страницы (иначе лаборатория
теряла бы то, что на экране); ручная правка этих файлов в редакторе
тоже видна только после перезагрузки страницы.

## 5. События и реакции

### 5.1. Механизм

Экраны приложения сообщают о том, *что произошло*, а не о том, что
должна сделать Юми:

```ts
bridge.handle('analysis:start');
bridge.handle('analysis:done', { confidence: 0.82 });
```

Таблица реакций решает, что Юми при этом делает. Поэтому смена
источника событий (фронт сейчас, сервер потом) не трогает экраны.
По желанию частые события схлопываются (`throttleMs` в `connect`); последнее
событие при этом всегда доходит.

### 5.2. Стандартные реакции (`DEFAULT_RULES`)

| Событие | Реакция |
|---|---|
| `request:start`, `inference:start`, `predict:start`, `loading`, `user:submit` | `thinking` |
| `search:start`, `retrieve:start` | `searching` |
| `analyze:start` / `compare:start` | `analyzing` / `comparing` |
| `request:done` | `success`; при `confidence` < 0.7 — `gentle`, < 0.4 — `curious` + «Я не уверена в этом результате.» |
| `inference:done` | `success`; при `confidence` < 0.5 — `curious` |
| `predict:done`, `done`, `ready` | `success` |
| `request:error` | `error` + «Что-то пошло не так. Попробуем ещё раз?» (текст исключения не озвучивается) |
| `error`, `failed` | `error` |
| `request:cancel` | `idle` |
| `request:retry`, `retry` | `retry` |
| `ws:open`, `connected` | `welcome` |
| `ws:close` | `idle` при чистом закрытии (1000), иначе `error` |
| `disconnected` | `error` |
| `user:input` | `curious` |

### 5.4. Сервер

Сервера пока нет. Когда появится OpenAPI-контракт, в нём отражаются
только поля, влияющие на реакцию (например, `confidence` в ответе
анализа). Поток событий с сервера (SSE / WebSocket) — по необходимости,
через `listenEventSource` / `listenWebSocket`.

## 6. Ошибки и деградация

| Ситуация | Поведение |
|---|---|
| Нет WebGL / рендерер упал | окна с картинкой нет, событие `error`; состояния и реплики работают |
| Модель не загрузилась | в окне только фон, событие `error`; состояния и реплики работают |
| Клип не загрузился | остаются лицо и свет; состояние «по концу клипа» уходит в покой по запасному таймеру |
| Обрезка `trim` длиннее клипа | клип играет целиком, предупреждение в консоли |
| Нет голосов в системе | реплика только текстом в пузыре |
| Источник голоса упал | речь прекращается, событие `error`, Юми не зависает в `speaking` |
| Отдельное окно не открылось (не Chromium, политика) | окно остаётся на странице, кнопка «□» в не-Chromium неактивна |
| Хранилище браузера недоступно | окно открывается на месте по умолчанию, ничего не запоминается |
| Картинка фона не загрузилась | тёмная заливка сцены, Юми видна |
| Исключение в правиле моста | событие пропускается, предупреждение в консоли |
| Исключение в слушателе `core.on` | остальные слушатели получают событие |
| Битая запись в файле данных | запись отбрасывается, остальные работают |
| Потеря WebGL-контекста | отрисовка на паузе до восстановления |

## 7. Нефункциональные требования

- **Вес:** на старте ≤ 2.5 МБ ассетов (модель 1.76 МБ + клипы покоя и
  фон 65 КБ); JS рендерера ~207 КБ gzip, грузится лениво; лаборатория —
  отдельный чанк ~13 КБ gzip.
- **Производительность:** когда Юми не видна (свёрнута, прокручена,
  закрыта, вкладка скрыта), кадры не рисуются. Фон — статичная картинка,
  без нагрузки на 3D.
- **Доступность:** меню и Юми управляются с клавиатуры; canvas и фон
  скрыты от скринридеров; реплика — `role="status"`;
  `prefers-reduced-motion` убирает фоновое движение, микро-движения
  глаз, пульсацию света и переезды камеры между кадрами клипов.
- **Безопасность:** запись файлов данных — только в режиме разработки
  (4.9); имена состояний и клипов из сети не находят свойства прототипа;
  текст исключений не озвучивается.
- **Совместимость:** Chrome / Edge — полностью; Firefox / Safari — без
  отдельного окна. three ≥ 0.170, React ≥ 18. Node для разработки и
  сборки — `^22.12 || ^24 || >=26` (так требует vitest 5; CI — Node 24).

## 9. Открытые вопросы

1. Таблица реакций продукта — после появления кейса.
2. Содержимое меню окна — пока стандартное, уточнится с продуктом.
3. Записанные реплики вместо синтеза — запишем позже: формат файлов и
   их список определятся тогда же (липсинк по звуку уже поддержан).
4. Известные ограничения: `success` у потоковых ответов приходит по
   заголовкам, а не по концу потока; одна картинка на ядро (второе окно
   забирает рендерер у первого); браузерный синтез глушит и чужую речь
   на странице; кадры клипов общие для всех рендереров на странице —
   правку из одного рендерера другой увидит при следующей смене клипа;
   при «снапе» камеры (resize, ползунки) глаза на миг возвращаются к
   центру и плавно догоняют курсор; режим `reducedMotion: 'auto'`
   читает системную настройку при создании рендерера, а не следит за её
   сменой; пиксельный шрифт по умолчанию грузится с Google Fonts
   (`font={false}` — без внешних запросов).
5. Стартовая страница `WindowDemo` — заготовка; заменится экранами
   продукта, когда появится кейс.

### Решено

- **Бинарные ассеты** (~14 МБ: модель, клипы, фон) хранятся в репозитории
  как есть — разрешено владельцем. Несжатые исходники модели
  (`assets-src/`, ~28 МБ) в репозиторий не входят; `npm run optimize`
  ждёт их локально.
- **Модель Юми** (`model/yumi.vrm`, «aspho_di») — работа участника
  команды, автор — **Ymi**. В метаданных VRM указаны условия
  (`allowRedistribution: false`, `modification: prohibited`,
  `avatarPermission: onlyAuthor`, `creditNotation: required`); автор
  разрешил публикацию модели в этом репозитории в рамках проекта — в
  сжатом виде (`npm run optimize`: meshopt и WebP, без изменения
  самой модели). Использование — некоммерческое
  (`commercialUsage: personalNonProfit`).
  Упоминание автора обязательно — оно есть в `frontend/README.md`.
  Брать модель в другие проекты без согласия автора нельзя.
- **Лицензии на анимации не оформлены.** Mixamo-клипы и танцы (MMD)
  опубликованы в репозитории по решению команды в рамках хакатонного
  проекта; при распространении модуля за пределами проекта их
  источники и условия нужно пересмотреть.
- **Лаборатория входит в сборку** отдельным чанком на `?view=lab`:
  она не утяжеляет стартовую страницу и помогает настраивать Юми на
  стенде («копировать JSON»).
