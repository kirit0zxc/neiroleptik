# Исполнитель команд агента: Low

Основной сетевой контракт — `commands.md` и `../contracts/openapi.json`.
Этот документ описывает локальное исполнение, не изменяя API центра. Предложения
из `runtime-contract-proposal.md` не определяют командный API. Сроки D1–D5,
lease 60 секунд, продление каждые 20 секунд и hard deadline центра сохраняются.
Medium/High/reset здесь не реализуются; неподдерживаемая команда получает failed ACK.

## Поток и устойчивое состояние

Один процесс агента владеет каталогом состояния через межпроцессный замок.
Команды разных deployments исполняются последовательно. Перед изменением Docker
в SQLite с synchronous=FULL фиксируются безопасные метаданные команды, fingerprint
неизменяемого тела, lease, новый UUID попытки start и стадия исполнения.
Конфигурация профиля и пароли не записываются: после рестарта конфигурация получается
повторным claim(command_id). Bearer хранится только в окружении; lease token находится
в закрытом каталоге состояния. Поддерживается локальный диск, не общий сетевой том.

Для каждого deployment отдельно сохраняются обработанное поколение, последний
instance_id и историческая applied_revision. Generation учитывает stop и ошибки;
пропуски допустимы. Повтор известного command_id проверяется раньше поколения.
Другой fingerprint того же ID — отказ без мутации. Новая команда с
expected_generation ниже обработанного — STALE_GENERATION. Итог без lease_token
фиксируется атомарно с историей deployment до отправки ACK и больше не меняется.

После потери ACK сначала повторяется сохранённый ACK с последним token: terminal
claim отвечает COMMAND_FINISHED. При LEASE_EXPIRED/LEASE_MISMATCH незавершённой
команды агент получает новый lease того же ID и повторяет неизменный результат.
После COMMAND_FINISHED для незавершённой локальной операции выполнение прекращается;
она сохраняется как abandoned, фактический контейнер остаётся для отдельного stop
из unknown. Ошибка ACK_MISMATCH/ACK_CONFLICT блокирует дальнейшую очередь и требует
исправления причины, а не удаления истории. Сетевой сбой оставляет запись для повтора.

## Lease и физические операции

Перед исполнением выполняется renew; во время работы lease продлевается отдельной
корутиной. Время ограничивается одновременно UTC сроками центра и монотонным таймером
локального lease. Ошибка renew или достижение срока закрывают разрешение на новые
мутации. Каждый run/stop/remove отдельно проверяет разрешение. Уже начатая Docker
операция может закончиться после потери lease: агент её не отменяет и не освобождает
слот до окончания. Последующая автоматическая очистка также запрещена без lease.
Наблюдение inspect допускается, результат сохраняется для последующего восстановления;
ACK старым token после потери lease не отправляется.

При остановке процесса ожидается окончание начатой операции. SIGKILL/сбой хоста
оставляет стадию executing: следующий процесс сначала claim+renew, затем сверка
Docker. Пока результат неоднозначен, новый start не повторяется автоматически.

## Сверка и ACK

UUID start сохраняется до run и передаётся фабрике LowDriver. Recovery проверяет
managed, deployment_id, level=low, instance_id и revision, неизменяемый container ID.
При найденном экземпляре текущей попытки start проводится health check, без нового
run. Если executing start не оставил контейнера, агент возвращает RECOVERY_UNCERTAIN:
не доказываем, что прежняя попытка никогда не выполнялась, и не запускаем её повторно.
Prepared означает, что мутация ещё не начиналась, поэтому после сверки её можно начать.
Чужой или некорректно маркированный контейнер не изменяется. Stop повторяем и
подтверждаем stopped только после inspect, подтверждающего отсутствие контейнера.
Удаление всегда по неизменяемому ID, без возврата к имени при гонке.

Успешный start: running, новая идентичность попытки, целевая revision, generation
команды. Обычный stop сохраняет прежнюю applied_revision и instance_id независимо
от очищенного DriverStatus.revision. Stop с reconcile=true может сохранить найденные
метки того же deployment, включая start, ACK которого центр не получил.
При сбое ACK содержит безопасный код и краткий текст без конфигурации и вывода Docker.
Running на неудачном start допускается только для ожидаемого прежнего instance;
новую неуспешную попытку нельзя выдавать за подтверждённый running.

## Приёмка

- HTTP claim/renew/ACK: Bearer, ограничения ответа/таймаута, запрещённые redirects,
  проверка полей и сроков, безопасные ошибки, соответствие OpenAPI.
- Start → настоящий LowService → ACK → stop, отдельно интеграция с FastAPI/PostgreSQL
  и Docker в CI/на согласованном сервере; подмена backend явно обозначается.
- Повтор terminal команды, потеря ответа ACK и рестарт не повторяют run.
- Stop и ошибки увеличивают generation, история revision/instance переживает рестарт.
- Потеря lease во время задержанного run не разрешает remove/следующий run;
  повторная выдача сверяет контейнер и выполняет health check.
- Hard deadline не продлевается, expired операция не блокирует отдельный stop из unknown.
- Проверены конфликт ID, stale generation, неожиданная идентичность контейнера,
  ошибки диска, взаимное исключение процессов и отключение сети.

## Связка с телеметрией

Новый Low JSONL пока не поддерживается адаптером Event v1. Для Димы предоставляется
генератор реальных строк `python -m infra.runtime.sample_low_journal` и отдельный
handoff с connection/HTTP/TCP/ротацией/усечением. Предложения из ответа телеметрии
не считаются подтверждением реализации: network.data, source_seq, UID/GID,
cleanup и квоты требуют окончательного согласования. Менять Event v1 в этом PR
не требуется. Cowrie/TTY примеры относятся к следующему этапу.
