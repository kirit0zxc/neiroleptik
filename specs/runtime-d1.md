# Runtime D1: локальный проверяемый блок

Статус: требования к первой реализации. Живой Linux/KVM-хост ещё не подготовлен.
Проверка этого блока не закрывает общий рубеж D1 «Low → центр → UI».

## Low

`LowService` открывает два ограниченных asyncio-сервера: TCP-баннер и HTTP.
Параметры `LowConfig`: IPv4/IPv6-адрес привязки, TCP/HTTP-порты, ASCII-баннер,
строковое тело HTTP, таймаут чтения, максимальный размер входа и число активных
соединений. Значения валидируются до открытия сокетов. По умолчанию привязка
только к `127.0.0.1`; порт 0 разрешён для тестов. Два одинаковых ненулевых порта
недопустимы. Баннер не допускает управляющие символы, кроме завершающего CRLF;
конфигурация не допускает команд, шаблонов shell и пользовательских путей.
CLI `python -m honeypots.low` добавляет CRLF к баннеру и LF к непустому тексту
страницы, если они не заданы, чтобы значения профиля передавались одной строкой
без управляющих символов; `LowConfig` при этом не меняется
(см. [runtime-drivers.md](runtime-drivers.md), раздел 7).

TCP отправляет баннер, считывает не более лимита и закрывает соединение по
таймауту/лимиту. HTTP читает ограниченные заголовки до CRLFCRLF; принимает
GET/HEAD с версией HTTP/1.0 или HTTP/1.1, отдаёт фиксированную страницу и закрывает
соединение. HEAD возвращает тот же Content-Length без тела. Слишком большой
запрос даёт 431, неверный синтаксис 400, неподдерживаемый метод 405; чтение имеет
общий таймаут. Нет доступа к файлам, проксирования, исполнения команд и отражения
полученных данных в HTTP-ответе. Произвольные входные байты в журнале кодируются
base64 и ограничиваются лимитом. События не выводят секреты конфигурации.

`EventSink` принимает локальные записи `connection` и `request` с UTC-временем,
протоколом, адресом клиента и ограниченной полезной нагрузкой. JSONL — внутренний
диагностический формат; до согласования общего Event его не отправляют в центр.
Ошибка записи не должна выдавать успешную обработку: соединение закрывается,
ошибка наблюдаема вызывающей стороной/обработчиком ошибок; неподтверждённые
данные не объявляются сохранёнными. Журнал не является устойчивым spool.

`start()` повторно не открывает серверы; при ошибке второго bind первый закрывается.
`stop()` закрывает слушатели и активные подключения и допускает повторный вызов.
Превышение числа соединений приводит к закрытию лишнего соединения без роста
неограниченной очереди задач. Необходимы реальные loopback-тесты TCP/HTTP,
ошибок/границ, частичного запуска, остановки и недоступного EventSink.

## Локальный журнал команд

`CommandJournal` использует SQLite на хосте и транзакции. Это внутренний механизм,
не HTTP API и не spool участника 4. Новый журнал имеет generation=0 и не имеет
экземпляра. Команда имеет UUID command_id, разрешённое действие start/stop/reset,
expected_generation и канонизируемый JSON payload. Сам журнал команды не исполняет.

Сначала проверяется повтор ID: совпадающее содержание возвращает прежнюю запись,
другое содержание отклоняется с COMMAND_CONFLICT. Новый ID с устаревшим поколением
отклоняется с STALE_GENERATION. Пока есть незавершённая операция, новая получает
BUSY. Успешное принятие записывается до возврата; generation не меняется при приёме.

Завершение start/reset с новым instance_id увеличивает generation ровно на один;
повтор идентичного завершения не меняет состояние. Stop сохраняет поколение и
последний instance_id для связи с доказательствами. Ошибка сохраняет поколение.
Нельзя завершить неизвестную команду или заменить терминальный результат другим.
Незавершённая команда после открытия нового объекта журнала остаётся pending,
не выполняется повторно автоматически и требует reconcile.

Входные generation — неотрицательные целые (bool недопустим). JSON не допускает
NaN/Infinity, нестроковые ключи, произвольные объекты и чрезмерный размер; UUID
нормализуются. Обязательные тесты: повтор после потери ответа, конфликт ID,
устаревшая команда, конкурентный приём, повтор завершения, сбой/переоткрытие.

## Preflight

`RuntimePreflight` выполняет только чтение окружения и ограниченные по времени
диагностические команды. Linux, /dev/kvm (символьное устройство и доступ), версии
qemu-img/virsh, подключение `virsh -c qemu:///system`, доступность ip и firewall
проверяются отдельными результатами PASS/FAIL/UNKNOWN. Команды запускаются списком
аргументов, без shell; stdout/stderr и время ожидания ограничены.

Проверка наличия бинарника, KVM или соединения libvirt не доказывает возможность
создания VM, изменения сети и сетевую изоляцию. Эти проверки всегда выделяются
как требующие отдельного живого smoke, а не PASS. На неподдерживаемой ОС проверка
выдаёт понятный отчёт и не запускает Linux-команды. CLI печатает JSON и возвращает
ненулевой код, если статические предпосылки не выполнены. Никакого изменения
firewall, создания VM, скачивания образов и запросов в чужую сеть нет.

## Приёмка и границы

Ruff, mypy, pytest, сборка Python wheel и проверка Compose-конфигурации выполняются
для локального блока. CI имеет отдельную runtime-задачу и не зависит от наличия
Django. Docker/KVM smoke, Cowrie PTY/exec/SFTP, общий Event/ACK, центр и UI требуют
интеграционного окружения и отражаются как невыполненные до фактического прогона.
