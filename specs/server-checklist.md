# Подготовка серверов владельцем backend

Для локальных проверок сервер не нужен: PostgreSQL запускается через Docker.

## Центр A

Ориентир для MVP: Linux, 2–4 vCPU, 4–8 ГБ RAM, 40–60 ГБ SSD, постоянный диск.
Понадобятся IP/домен, SSH-пользователь и уже настроенный SSH-доступ; приватные
ключи и пароли не присылать в чат. До внешнего запуска: HTTPS, firewall,
защищённый mgmt-маршрут, резервное копирование БД и ключа шифрования credentials.
БД не публикуется наружу. HF_COOKIE_SECURE=true, реальные allowed origins.
.env генерируется локально и не коммитится. Не включать доверие произвольному
X-Forwarded-For: доверенный proxy задаётся явно.

## Runtime B — согласовать с участником 3

Отдельный Linux-хост с подтверждёнными /dev/kvm, libvirt и сетевыми правами.
Ориентир 4–8 vCPU, 16 ГБ RAM, 80–120 ГБ SSD. До оплаты подтвердить разрешённость
стенда у провайдера и nested virtualization либо выбрать выделенный сервер.
Подготовка High и проверка изоляции принадлежат runtime-разработчику; владелец
серверов выдаёт доступ и согласует firewall. Не открывать guest путь к центру.

## Перед размещением

Проверить TLS, секреты, restore, версии миграций, health, права SSH, журнал ошибок.
Локальный compose.center.yml — dev-контур, не готовая публичная конфигурация.
Публикацию и DNS/TLS делаем отдельным этапом после получения параметров сервера.
