# Матрица проверок следующего этапа телеметрии

Это требования к будущим автотестам, не отчёт о выполнении. Реализовать проверки поведения из 02_SPEC.md. Для каждой проверки отчёт содержит команду, окружение, результат и доказательство. Тестовые fixtures не выдавать за реальные записи Cowrie или production Low mapping.

## Конверсия и SQLite

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| C01 | Новый валидный Event из сохранённой raw-позиции | Один pending и один ledger; исходные bytes и raw-checkpoint неизменны |
| C02 | Header/footer дают служебный результат | Ledger есть, Event отсутствует; повтор безопасен |
| C03 | Mapper бросает исключение или возвращает невалидный Event | Нет новых pending/ledger, исходная позиция доступна для повтора |
| C04 | Ошибка после INSERT pending, после ledger, перед commit | Каждая точка откатывает всю пару, ранее сохранённые записи остаются |
| C05 | Отдельный процесс аварийно выходит до и после commit | После открытия БД либо обе записи, либо ни одной; повтор достраивает без дублей |
| C06 | Одинаковая позиция повторена до ACK, после ACK и после рестарта | Повторной pending нет; ledger переживает удаление подтверждённого Event |
| C07 | Permanent/retryable отказ для созданного Event | Quarantine/pending соответствуют ACK; повтор raw не создаёт второй Event |
| C08 | Конфликт raw, Event ID или результата, новая версия mapper | Нет перезаписи оригинала и повторной отправки; явный безопасный результат |
| C09 | Два соединения одновременно конвертируют одну позицию | Одна итоговая pending/ledger; проигравший получает повтор либо контролируемый retry |
| C10 | Лимиты шага, writer-lock, квота/ошибка записи | Ограниченный шаг, корректный прогресс, нет ложного успешного checkpoint |
| C11 | Непустая существующая spool со snapshots/quarantine/checkpoints | Старые append/ACK и сохранённые данные совместимы после добавления ledger |

Инъекции должны попадать в реальную транзакцию, а не проверять только имитацию repository. Crash процесса не доказывает устойчивость к физическому отключению питания.

## Настоящий PostgreSQL и тестовый HTTP

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| P01 | Sender отправляет batch через HTTP | ACK после commit; видны реальные event/outbox |
| P02 | Ответ потерян после commit, sender перезапущен и повторяет | Те же Event и canonical payload; по одной event/outbox/publication |
| P03 | Storage commit не завершён или откатился | Нет положительного ACK и частичной фиксации |
| P04 | Новый B, конфликтующий A, новый C в одном batch | B/C приняты, A rejected с правильным index; оригинал A неизменен |
| P05 | Конкурентные одинаковые и разные payload одного ID | Идемпотентный успех либо конфликт; UNIQUE обеспечивает одну запись |
| P06 | Publisher crash до/после commit | До commit нет видимой публикации; после restart максимум одна |
| P07 | REST snapshot и поздний commit во время пагинации | Стабильные страницы, без пропуска/подмешивания данных после watermark |
| P08 | WS reconnect во время публикации, REST-догрузка разрыва | Все ожидаемые пары ID получены; транспортные повторы допускаются и дедуплицируются клиентом |
| P09 | Одинаковый event_id у двух агентов, stream_seq >2^53 | Пары не склеиваются; bigint не теряет точность |
| P10 | Неверный/истёкший cookie, Origin, отзыв во время простоя WS | Доступ прекращён согласно существующему контракту |
| P11 | Тестовая маскирующая политика | REST/WS не выдают тестовые secrets; canonical оригинал не изменён |
| P12 | Неверный batch/ACK, 503, timeout и восстановление | Sender не теряет неподтверждённые данные и соблюдает backoff |

Использовать отдельную тестовую схему/БД и принятый в репозитории lock-wrapper. Не удалять общую базу. Проверять подключённые реальные компоненты, не заменять publisher или REST/WS словарями. Production identity/исторические instances проверяются отдельно после согласования.

## Нагрузка и восстановление

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| L01 | Известный поток при доступном и недоступном приёмнике | Измерены backlog, ingress/drain rate, DB/WAL/SHM, свободный диск и задержки |
| L02 | Возврат связи после ограниченного outage | Все ожидаемые ID/payload доставлены; backlog уменьшается при достаточной мощности приёмника |
| L03 | SQLITE_FULL/ошибка write/commit | Нет потери ранее принятого сырья/событий и ложного продвижения ledger |
| L04 | Реальный ENOSPC в ограниченном тестовом volume, если доступен | Контролируемая ошибка и восстановление после освобождения места; системный диск не заполняется |
| L05 | Снятие ограничения и рестарт | БД открывается, pending сохраняется, доставка продолжается без повторных Event |

Малые детерминированные сценарии — обычный CI; продолжительная нагрузка и реальный disk-full — отдельный явный запуск с лимитами времени/объёма. Отсутствие L04 указать, не заменять его утверждением по L03.

## TTY и автоматический сценарий

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| T01 | Ввод/вывод, ASCII и Unicode на фиксированной записи | Сохранены текст, направление и время по описанному тестовому формату |
| T02 | UTF-8 символ разбит между блоками; неверные bytes | Нет тихой потери; результат/ошибка соответствует явной политике |
| T03 | EOF внутри header/payload, неизвестный тип, чрезмерная длина | Явная неполнота/ошибка, ограниченная память, нет фиктивного полного replay |
| T04 | Равные/обратные timestamps, пустой файл, управляющие коды | Детерминированная политика; содержимое не исполняется как HTML/команды |
| E01 | Скрипт Event→outage→restore→PostgreSQL→REST/WS | Сверены точные пары ID и canonical payload, публикации и восстановление очереди |
| E02 | Повтор всего сценария и cleanup | Запуски изолированы, ресурсы закрыты, нет зависимости от прошлой базы |
| E03 | Недоступный PostgreSQL/порт, незавершённая доставка | Ненулевой выход и понятный отчёт; не ложный успех |
| E04 | Реальный Low→Event→БД→UI | Отложен до согласования mapper и production wiring; отдельная приёмка без моков |

## Уточнения после ответов backend/runtime

| ID | Требование | Статус независимого этапа |
| --- | --- | --- |
| N01 | Rename/replay сохраняют identity; одинаковый offset разных journal не склеивается | Старый adapter/reader неизменны; синтетический raw converter проверяет разные journal; production golden UUID ещё совместно закрепить |
| N02 | Новый процесс того же instance: null predecessor, продолжающийся journal_seq, повтор seq, старые checkpoints сохраняются | Исполняемый тест конверсии сохранённого raw; переход collector через разрыв не разрешён |
| N03 | Полные строки без footer, tail без LF, последующее завершение LF один раз | Существующие durable/reader тесты сохраняются и запускаются |
| N04 | Сессия через rotation/без первой connection; разные connection одного IP | Отложено до общего session UUID/DTO mapping; по IP не склеивать |
| N05 | Исторический instance accepted без running; чужой rejected; не зарегистрирован retryable | Подтверждённые требования; production authorization/lifecycle тесты совместно с backend |
| N06 | source=null только после общего обновления схем/backend/frontend | Сейчас старая схема отклоняет; test ingress partial ACK проверен; nullable схема отложена |
| N07 | Явная полнота, gap, truncation, unknown; footer не доказывает full; нет выдуманного HTTP 200 | Точные mapping поля отложены, runtime/source факты зафиксированы |
| N08 | Согласованная маска REST/WS/export; изменение скрытого оригинала → conflict | Password REST/WS и immutable canonical conflict исполнены; полный allowlist/export отложены |
| N09 | ACK при остановленном publisher после commit event+outbox | Исполняемый настоящий HTTP/PostgreSQL тест |
| N10 | Repeat start/rotation/stop/recovery не создают новый instance, новая попытка создаёт | Существующие runtime тесты; lifecycle владельца не дублируется |
| N11 | Cleanup: bad hash/size, active writer, tail, receipt repeat, crash/delete, replay без predecessor | Отложено: receipt и recovery contract не определены; удаления нет |
| N12 | Linux read-only журнал/невозможность delete + writable spool | Отдельный Linux-стенд, Windows не доказательство |
| N13 | Sink отказ/новые подключения/TCP banner до failed request, admission/recovery | Текущие факты сверены; SQLite guarantees измерены отдельно; runtime disk-pressure стенд отложен |

Backend/runtime ответы не заменяют ответ Дианы и не разрешают неявное расширение
Event/API/migration. Оборванный конец runtime ответа не превращать в тестовое ожидание.

## Проверки перед передачей

Запустить относящиеся к изменениям pytest, Ruff check/format, mypy, экспорт контрактов и сборку затронутых пакетов по конфигурации репозитория. Проверить совместимость с актуальным main и импорт установленного wheel при изменении упаковки. Не запускать backend-тесты одновременно с другим владельцем общей БД вне lock-wrapper. Не выдавать skipped или инфраструктурные ошибки за успех.

Перед push выполнить цикл трёх субагентов из AGENTS.md на окончательных файлах. В отчёте отдельно показать: внутреннюю конверсию, тестовую PostgreSQL-интеграцию, нагрузочные измерения, тестовый TTY и отложенную production-приёмку.
